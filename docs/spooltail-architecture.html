Spooltail broker

One Rust process · Axum / Tokio
HTTP operationsPublish, look up a task, manage leases and advance group cursors. Store access shares one mutex.
SSE and WebSocket subscriptionsReplay indexed task events, then wait on an in-memory notification. A commit wakes readers to query again.

Persistent data directory

SQLite index and subscription stateTask and event IDs map to offsets and segment locations. SQLite also holds work leases, group cursors and retention floors.
Append-only journal segmentsChecksummed frames hold event payloads. A terminal completion frame also records the lease it acknowledges.
Follow a random status read
  1. The caller sends the topic and task ID to /latest.
  2. SQLite locates the latest retained record. The broker reads that frame from the journal and verifies its checksum.
  3. The caller receives the event and its offset, or HTTP 404 if no retained status exists.
Follow an atomic task completion
  1. The worker submits its work offset, lease generation and terminal status event.
  2. The broker validates the lease and flushes the completion frame to the journal. One SQLite transaction indexes the status and marks the lease done.
  3. After commit, the broker wakes task subscribers and returns the status offset. An exact retry returns that same offset.
Follow a subscriber after reconnect
  1. The client supplies its last event ID through SSE or WebSocket. A fresh subscription starts at the first retained event for the task.
  2. The broker registers for wakeups and replays retained records after that ID. An unknown or expired ID produces a gap.
  3. Once caught up, the subscriber waits for the next commit. A terminal status ends that task’s subscription.
